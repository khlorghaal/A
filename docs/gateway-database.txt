Gateway and database draft
├─ pseudocode describes target; implemented components listed separately below
├─ gateway: separate executable, TLS over TCP, framed custom messages; no HTTP
├─ peers: UDP, own auth; blastd receives authenticated lifecycle/data from host
├─ gateway issues session token; peers verify token/proof locally
│  └─ auth internals and wire format await user spec; auth calls below placeholders
└─ gateway serves discovery/trust; no game simulation or gameplay relay

Current implementation
├─ src/gateway_main.nim: standalone preflight; validates TLS/config/database lease
│  └─ make gateway builds executable; live mode exits 2 before opening listener
├─ gateway report deletion uses revisioned tombstones; excluded from aggregation
│  but retained until fresh source session; saved v2 reads legacy v1 report state
├─ report-key quota defaults 65536; state save/load byte limit defaults 16 MiB
│  └─ limits configurable; existing-key updates still allowed at report cap
├─ bounded async listener: per-connection handler factory, concurrent-connection cap,
│  tracked child cleanup and idempotent close; host still supplies actual auth
├─ gateway TLS context and async connection handler: TLS >=1.2, bounded frames,
│  partial-frame/write deadlines; host supplies admission limits and auth handler
│  └─ loopback TLS, silent peer and trickled partial-frame deadline tests pass
├─ gateway.json persists private roles and report provenance via shared atomic writer
│  ├─ sessions never persist; reconnect starts fresh source snapshot/revisions
│  └─ gateway weights remain injected; user accounts/auth fields still absent
├─ src/gateway.nim: report-state core; host supplies authenticated session epochs
│  and immutable previous-score weights; auth wiring/standalone executable pending
│  ├─ one report per reporter/subject; stale revisions and old sessions rejected
│  ├─ demotion deletes source reports/session; fresh session clears source snapshot
│  └─ membership private; callback weighting keeps unresolved policy injectable
├─ src/gateway_snapshot.nim: draft v1 JSON envelope with paragon rows
│  ├─ bounded input bytes/entry count; NFC IDs, unique subjects, finite [0,1] values
│  └─ auth and server wiring external; schema provisional, no deployed compatibility
├─ trustdb bootstrap priors persist separately; witness broadcasts omit prior-only W
├─ syncParagon performs manual full replacement and commit-before-publish;
│  gateway operation dispatch/authorization still pending; snapshot codec provisional
├─ src/gateway_frames.nim: bounded four-byte big-endian length framing; opaque body
│  └─ tests cover fragmented/coalesced input, empty/binary payload and truncated EOF
├─ src/trustdb.nim: NFC IDs, witnessed/paragon scalar stores, volatile swarm edges
│  ├─ witnessed value and discredit persist; paragon aggregate persists
│  ├─ refresh weights swarm reports by previous combined reporter credibility
│  └─ save validates full state, then atomically replaces trust.toml; POSIX fsync
│     covers staged file and parent directory
├─ src/trustsync.nim: firsthand reports only; bootstrap row and later updates
│  ├─ report key = reporter/subject; revision watermark currently PeerId/subject
│  └─ no reporter restart epoch, deletion protocol, or paragon classification
├─ client loads/saves trust; trust-policy integration with live game still pending
└─ tests/socket_gateway.nim: loopback UDP test relay; not production gateway

Data ownership
├─ peer durable
│  ├─ witnessed[subject] = local credibility and discredit; bootstrap W from average P
│  │  └─ later remote reports never directly overwrite local W
│  └─ paragon snapshot[subject] = gateway-supplied aggregate; replace as one generation
├─ peer volatile
│  ├─ reports[reporter, subject] = value, report epoch/revision, local receipt time
│  ├─ combined[subject] = derived score; rebuild after load or updates
│  ├─ reliability[connection] = locally measured ping-derived score
│  └─ bootstrap contacts and any permitted paragon classification; refresh on login
├─ gateway durable
│  ├─ users[id] = account record; auth-owned fields opaque to this draft
│  ├─ paragons[id] = gateway role membership; private administrative data
│  ├─ trust_swarm[reporter, subject] = accepted firsthand report with provenance
│  └─ trust_paragons[subject] = derived credibility snapshot from paragon reports
└─ gateway volatile
   ├─ active connections: principal, role, buffers, deadlines, subscriptions
   ├─ recent signins and bootstrap contacts: bounded; no reliable logoff knowledge
   └─ pending handoffs and snapshot generations

Open storage choices
├─ peer swarm persistence: current volatile behavior versus historical durable-store goal
├─ gateway report retention, source expiry and account deletion policy
├─ bootstrap defaults: new-account P=.5; S=0; peer W=mean(current P values)
│  ├─ empty P fallback .5; seed only previously unseen subjects
│  ├─ uniform fresh P=.5 yields combined .4; heterogeneous P yields subject-specific
│  │  initial score, not forced .4 for every subject
│  ├─ preserve existing W across login/manual sync; persist prior/observed marker
│  └─ prior alone never enters witness broadcasts; local observation establishes
│     firsthand value under existing credibility rules
├─ gateway reporter weight source: combined credibility needs defined inputs;
│  gateway observes no gameplay, so cannot manufacture firsthand witness scores
└─ derived cache persistence optional; authoritative input must allow reconstruction

Aggregation rule
├─ one current opinion per reporter/subject; repeated packets replace, never add votes
├─ category contribution = mean(previous_combined[reporter] * reported_value)
│  ├─ denominator = reporter count, not sum of weights; preserve existing rule
│  └─ absent category contributes zero; reject nonfinite/out-of-range input
├─ next_combined = .4*witnessed + .4*paragon + .2*swarm
├─ compute all next scores from same previous snapshot, then swap once
│  └─ fixed scheduled step; no iteration per incoming packet or until convergence
├─ reliability stays local; never import remote ping/reliability recommendations
└─ paragon component source unresolved: gateway aggregate versus direct weighted
   paragon reports; avoid counting same report in both .4 and .2 categories

Paragon visibility: unresolved policy conflict
├─ existing notes hide gateway paragons but also mention client paragon lists
├─ direct paragon classification requires client to know reporter category
├─ recommended A: gateway privately aggregates paragons; client receives aggregate
│  plus bootstrap contacts without exposing complete membership
├─ candidate B: client receives explicit membership and classifies direct reports;
│  changes privacy promise and needs explicit choice
└─ draft leaves choice open; friend trust remains deferred

Private membership versus public: tradeoffs
├─ recommended client model: consume gateway trust_paragon aggregate; no direct
│  paragon classification or special treatment of individual peer reports
├─ private: smaller client protocol/state; gateway owns membership and weighting
│  ├─ client cannot independently reweight gateway's individual paragon evidence
│  ├─ paragon DB sync manual; no periodic refresh; snapshot may stay stale
│  └─ behavior/contact patterns may reveal membership; not guaranteed secrecy
├─ public: client can classify and weight direct paragon reports, audit source
│  attribution and respond to membership changes; extra distribution, freshness,
│  provenance and reclassification machinery; disclosure identifies role holders
├─ same underlying opinion may arrive through gateway aggregate and peer swarm
│  └─ correlated evidence remains possible even without duplicate source records;
│     accept overlap explicitly or design provenance/filtering, with privacy cost
├─ bootstrap contacts need no explicit paragon labels under recommended model
└─ manual paragon DB sync needs gateway operation for ordinary authenticated
   clients; distinguish snapshot request from paragon-only ongoing report channel

Pseudocode: report ingestion, shared conceptual operation
  receive_report(connection, message):
    reporter = connection.authenticated_player_id   # never trust body reporter
    validate subject NFC, finite value in [0,1], sizes and quota
    validate source epoch/revision under host session lifecycle rules
    reject stale or duplicate report
    classify reporter using selected paragon policy
    replace reports[reporter, subject]
    mark derived scores dirty

  aggregation_step(dt_seconds):
    advance local witnessed credibility using existing evolution, if peer
    previous = copy(combined)
    for subject in known_subjects:
      paragon = selected_paragon_component(subject, previous)
      swarm = mean(previous[reporter] * report.value for eligible swarm reports)
      next[subject] = .4*witnessed[subject] + .4*paragon + .2*swarm
    combined = next

Pseudocode: gateway lifecycle
  start(config):
    open and validate database; obtain exclusive writer ownership
    load TLS configuration; verify startup before accepting clients
    listen TCP; enforce connection, handshake and buffer limits

  on_tls_ready(connection):
    principal = auth.authenticate(connection)       # deferred user specification
    if authentication fails: close
    if account creation authorized:
      create account transactionally; NFC uniqueness enforced at commit
    credential = auth.issue_session(principal)     # deferred user specification
    snapshot = capture_consistent_trust_and_contact_snapshot(principal)
    send framed handoff(credential, snapshot)
    if principal currently in gateway.paragons:
      enter bounded paragon report channel
    else:
      finish handoff and close                     # post-signin traffic restricted

  on_paragon_frame(connection, frame):
    check current role again                      # role may change during session
    dispatch allowed report/snapshot request only
    receive_report(connection, frame)
    schedule aggregation and durable checkpoint

  scheduled_work():
    expire stale contacts/reports according to selected policy
    aggregate on fixed cadence, publish new snapshot generation
    checkpoint dirty database; flush on controlled shutdown

Pseudocode: peer bootstrap and witness exchange
  gateway_handoff(config):
    connect TCP with TLS; verify gateway identity
    credential, snapshot = auth.login_and_receive_handoff()  # opaque auth step
    stage bounded, validated snapshot; commit complete generation only
    replace gateway-derived aggregate and volatile bootstrap state
    keep local witnessed/discredit records
    start peer transport with credential           # peer auth deferred

  peer_authenticated(connection):
    bind transport PeerId to authenticated player/session
    send complete firsthand witness snapshot with bounded framing/chunks
    then publish firsthand deltas through blastd

  peer_report(connection, report):
    receive_report(connection, report)
    never republish received opinion as local firsthand evidence

  snapshot_or_delta_delete(connection, subject):
    validate freshness; remove source opinion or apply tombstone
    # deletion, snapshot completeness and restart epochs need protocol definition

Persistence proposal: basic transaction
├─ one writer; one state file per database directory
│  ├─ peer trust.toml; gateway gateway.json; auth-owned account storage still pending
│  └─ atomic writer holds nonblocking POSIX file lease; client additionally holds
│     directory .owner.lock across load/run/save; gateway startup must do same
│  └─ logical tables share file so one replacement commits complete state
├─ stage complete update in memory; validate all tables before touching live state
├─ write same-directory temporary file; flush/fsync; atomic rename over live file
│  └─ sync parent directory for crash durability; publish staged memory after commit
├─ before rename failure leaves old file; after rename restart loads complete new file
│  └─ directory-sync failure means durability uncertain; report error, no blind retry
├─ startup ignores abandoned temp file; malformed live state fails explicitly
├─ migrate legacy files only when new file absent; leave originals until commit succeeds
├─ no transaction across peer and gateway; each handoff commits locally after validation
├─ quotas bound report count, subject count, snapshot bytes and checkpoint size
└─ test gateway uses build/gateway/db; automated tests use isolated temporary dirs

Work breakdown, suggested sequence
├─ settle paragon visibility/category source, gateway weight/bootstrap and retention
├─ database schemas: provenance, single-file transaction, bounds, legacy migration
├─ report ingestion/aggregation independent from network; deterministic tests first
├─ gateway executable and bounded TLS/TCP framing; auth callback only in test harness
├─ handoff snapshot staging, replacement and bootstrap contact lifecycle
├─ role-gated paragon report channel, aggregation, checkpoint and recovery
├─ connect client trust policy/witness exchange once authenticated source binding exists
└─ auth implementation and live registration/login await user spec

Failure cases and required checks
├─ TCP read may contain partial or multiple messages; length limits before allocation
│  └─ tests: fragmented/coalesced frames, oversize declaration, disconnect mid-frame
├─ slow connections/handshakes and repeated signins can exhaust memory or descriptors
│  └─ tests: quotas, deadlines, bounded output queues, shutdown with pending I/O
├─ TCP remote endpoint is not verified UDP reachability; NAT may block peer discovery
│  └─ bootstrap contact is hint, not proof; stale/unreachable contacts expected
├─ crash/disk failure during transaction; rename alone not crash durability
│  └─ tests: interruption before/after rename, disk full, malformed live file, stale temp
├─ concurrent gateways/processes can overwrite state or race username registration
│  └─ tests: exclusive writer and normalized-name uniqueness; replication deferred
├─ restart resets report serial, while previous watermark may reject all new reports
│  └─ tests: restart, reconnect, PeerId reuse, delayed old-session packet, revision wrap
├─ missing report deletion leaves stale credibility indefinitely
│  └─ tests: empty/full snapshot replacement, tombstone order, expiry, dropped delta
├─ low-trust identities can dilute mean through reporter-count denominator
│  └─ test explicit dilution; admission/Sybil policy unresolved, not solved by signatures
├─ circular recommendations amplify correlated evidence; recompute cadence affects result
│  └─ tests: cycles, packet-rate independence, simultaneous previous-score evaluation
├─ paragon role changes alter category and permission while connection remains open
│  └─ tests: demotion, reclassification, no double-counting, snapshot privacy
├─ IDs may normalize equal, contain delimiters or huge Unicode strings
│  └─ existing NFC checks plus byte limits; never use player ID as filesystem path
└─ zero bootstrap weights may suppress every report; component seeds must yield .4
   └─ tests: empty database, new account, only unknown reporters, repeated restarts
