---
name: ordered-checklist
description: Track multi-part work in priority order without inventing execution dependencies.
---

For multi-part work, keep a brief temporary checklist in the task's scratch area.
Preserve the user's list order for priority and traceability; execute tasks in
any useful order unless the user specifies a sequence or a real dependency
requires one. Do not infer a dependency from list position alone.

Track completed, available and blocked work. For a blocker, name its missing
condition and only the tasks it affects. Continue with other available tasks;
revisit a blocked task when its condition changes. Preserve explicit constraints
and stop/pause points. A pause requested by the user remains a pause.

Revisit the checklist as scope changes and before declaring completion or a
global blocker. Remove it when finished unless a durable handoff is useful.
Skip checklist ceremony for a single simple request.
